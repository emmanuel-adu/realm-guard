# v1 plan: one scan, one report

**Journey:** drop an exported n8n workflow (and optionally a client manifest, or draft one in the app) and get a report of tenant-boundary problems. Every finding names the node, what was seen, why it matters and how to fix it. The report copies as Markdown.

## Engine (`src/engine`, no DOM)
1. `parseWorkflow(text)`: n8n editor export, CLI export (single-item array) or canvas copy. Normalizes credentials (`{id,name}`, bare string, `{name}`), edges (`main`, `ai_tool`, `ai_memory`), pinned data and disabled nodes. 5 MB cap.
2. `parseManifest(text)`: YAML or JSON. Realm IDs keep every digit (parsed as BigInt). Errors carry line numbers.
3. `draftManifest(workflow)`: one tenant per QuickBooks credential plus any literal realm IDs, ready to edit.
4. `scan(workflow, manifest?)`: finds QuickBooks touchpoints (QuickBooks node, its agent-tool form, HTTP Request calls to the QBO API), resolves each to clients, then runs the rules below.
5. `reportToMarkdown(report)`.

## Rules
| ID | Rule | Severity |
| --- | --- | --- |
| RG100 | No manifest: client checks skipped | gap |
| RG101 | Credential not in manifest | high |
| RG102 | Credential belongs to a client outside this workflow's scope | critical |
| RG103 | QuickBooks step has no credential in the export | gap |
| RG104 | One credential serves several clients | high |
| RG105 | Token built at runtime from workflow data | high |
| RG106 | Token pasted into the node | high |
| RG201 | Realm ID comes from an expression | high, critical when AI picks it |
| RG202 | Realm ID belongs to an out-of-scope client | critical |
| RG203 | Realm ID not in manifest | high |
| RG204 | Realm ID and credential belong to different clients | high |
| RG301 | Data from one client's books reaches a write to another's | critical |
| RG302 | One AI agent holds tools for several clients | high, critical with a write tool |
| RG303 | AI memory with a fixed session key | high multi-client, medium single |
| RG304 | Code node keeps workflow static data across clients | high |
| RG401 | Write with no approval step on the way | high, critical after AI, medium manual-only |
| RG402 | Agent write tool not behind a human review step | critical |
| RG403 | Approval step whose answer nothing checks (added after the fresh-eyes review) | high |
| RG501 | Export carries pinned data | low |

Verdict order: fix (any critical/high) > not verified (coverage gaps) > review (medium/low) > clear. No QuickBooks steps gives "nothing to check".

## UI
Single page: inputs (two drop zones with paste, samples, draft manifest), then verdict panel, findings with severity filters, touchpoint table, and what the scan can't see. Light and dark.

## Tests
Vitest for every rule and parser path (tests first). Playwright for the journey at 1440 and 390, keyboard, both themes, empty and error states. A robustness run over 2,066 public workflow exports (not committed).
